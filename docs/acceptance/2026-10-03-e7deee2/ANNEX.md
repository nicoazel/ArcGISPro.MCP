# Annex added after the run, not produced by run-acceptance

This file was written by hand after `tools/run-acceptance.ps1 -Commit` produced this folder. It is not part of the run's output, is not listed in `SHA256SUMS`, and changes none of the files the run produced. It records facts about how the run was carried out that the run itself could not record (`-RunNotes`, which now records such notes in `manifest.json` and `summary.md`, did not exist yet). See [the folder contract](../README.md#folder-contract).

- **Who decided the cards.** The eight approval cards of the `operations` section were decided in the MCP Studio dockpane by Claude (Anthropic's assistant) through computer use, at the maintainer's direction, not by the maintainer's own clicks. The card contents were checked against the console prompts before each click; seven were approved and the DENY card was denied.
- **One card expired and was re-queued.** The first card for `project.open` expired undecided after two minutes (`operations/results/115-approval.status-project-open-approved.result.json`, status `expired`) and the script queued it again (`116-approval.request-project-open-approved`), which was then approved. `operations/summary.json` records this as `approvals.queued: 9` and `approvals.expired: 1` for `approvals.requested: 8` card cases (7 approved, 1 denied, 0 skipped).
- **A modal ArcGIS Pro prompt was answered during the final `project.open`.** While the approved `project.open` ran, ArcGIS Pro showed its modal "Save all edits?" prompt, because the matrix's feature edits were still pending in the edit session. It was answered "Yes" by the same means (Claude through computer use, at the maintainer's direction) so the run could finish. That answer is what saved the matrix's feature edits: `project.save` at this commit (e7deee2) saved only the `.aprx`, not pending feature edits. The prompt is a defect, since an MCP client cannot answer it; later commits make `project.open` refuse with `pending_edits` and make `project.save` save pending edits first (see the CHANGELOG).
- **Why `project.open` took about 277 s.** The audited `project.open` operation ran from 05:43:05.126Z to 05:47:42.437Z (`audit.jsonl`), about 277 s, because the call waited on that modal prompt. The case's `durationMs` in `operations/summary.json` (409288) also includes the card wait and the re-queue.
